Your First Zig Program

Hands-on: set up Zig, write a small program, run the tests. By the end, your tools work and you've written real Zig.

zig exercise 20 min

Install Zig

# macOS brew install zig # Or download directly from ziglang.org/download # Pick your platform, unzip, add to PATH

Verify it works:

$ zig version 0.14.0

Any 0.13+ version works. Don't chase the latest nightly.

2

Create a scratch project

This is a throwaway project for learning. We'll set up the real Monk project structure later.

mkdir zig-scratch && cd zig-scratch zig init

This creates:

build.zigBuild configuration
src/main.zigYour code goes here
src/root.zigLibrary entry (can ignore)
3

Hello world

Replace the contents of src/main.zig with:

const std = @import("std"); pub fn main() void { std.debug.print("Hello from Zig!\n", .{}); }
$ zig build run Hello from Zig!

What you're seeing: @import("std") loads Zig's standard library. pub fn main() is the entry point. .{} is an empty tuple — the format arguments (none needed here).

4

Exercise: Count vowels

Your task

Write a function count_vowels that takes a string and returns how many vowels (a, e, i, o, u) it contains. Write a test first (TDD!), then make it pass.

This exercises: string iteration, conditionals, functions, and testing. These are the same patterns the lexer will use.

Step 1: Write the test first (Red)

Create a new file src/vowels.zig:

const std = @import("std"); pub fn countVowels(input: []const u8) usize { // TODO: implement _ = input; return 0; } test "empty string" { try std.testing.expectEqual(@as(usize, 0), countVowels("")); } test "hello has 2 vowels" { try std.testing.expectEqual(@as(usize, 2), countVowels("hello")); } test "all vowels" { try std.testing.expectEqual(@as(usize, 5), countVowels("aeiou")); } test "no vowels" { try std.testing.expectEqual(@as(usize, 0), countVowels("xyz")); } test "uppercase vowels" { try std.testing.expectEqual(@as(usize, 3), countVowels("HELLO WORLD")); }

Run the tests — they should fail (all expect non-zero but the function returns 0):

$ zig build test 2/5 passed, 3 failed.

Step 2: Make it pass (Green)

Now implement the function. Try it yourself before looking at the solution.

Show solution
pub fn countVowels(input: []const u8) usize { var count: usize = 0; for (input) |char| { switch (char) { 'a', 'e', 'i', 'o', 'u', 'A', 'E', 'I', 'O', 'U' => { count += 1; }, else => {}, } } return count; }
$ zig build test All 5 tests passed.

What you just learned:

  • Iterating over a byte slice with for (input) |char|
  • Pattern matching with switch (multiple values in one arm)
  • Mutable variable with var
  • TDD: test first, fail, implement, pass

These are exactly the patterns the lexer uses. Iterate characters, match patterns, accumulate results.

5

Exercise: is_digit and is_alpha

Your task

Write two functions: isDigit(char: u8) bool and isAlpha(char: u8) bool. The lexer will use these to identify numbers and identifiers.

Write tests first. A digit is '0' through '9'. An alpha is 'a'-'z', 'A'-'Z', or '_'.

Show solution
pub fn isDigit(c: u8) bool { return c >= '0' and c <= '9'; } pub fn isAlpha(c: u8) bool { return (c >= 'a' and c <= 'z') or (c >= 'A' and c <= 'Z') or (c == '_'); } test "isDigit" { try std.testing.expect(isDigit('0')); try std.testing.expect(isDigit('9')); try std.testing.expect(!isDigit('a')); try std.testing.expect(!isDigit(' ')); } test "isAlpha" { try std.testing.expect(isAlpha('a')); try std.testing.expect(isAlpha('Z')); try std.testing.expect(isAlpha('_')); try std.testing.expect(!isAlpha('0')); try std.testing.expect(!isAlpha(' ')); }

Direct preview of the lexer: these two functions are literally what the lexer calls to decide "is this the start of a number?" or "is this the start of an identifier?" You're already building compiler infrastructure.

Exercise: A tiny token

Your task

Define a TokenKind enum with variants number, plus, eof. Define a Token struct with fields kind and text. Write a test that creates a token and checks its fields.

Show solution
const std = @import("std"); const TokenKind = enum { number, plus, eof, }; const Token = struct { kind: TokenKind, text: []const u8, }; test "create a token" { const tok = Token{ .kind = .number, .text = "42", }; try std.testing.expectEqual(TokenKind.number, tok.kind); try std.testing.expect( std.mem.eql(u8, "42", tok.text) ); } test "eof token" { const tok = Token{ .kind = .eof, .text = "", }; try std.testing.expectEqual(TokenKind.eof, tok.kind); }

This is a miniature version of Monk's token system. In Phase 1, you'll expand this to 50+ token kinds covering every keyword and operator.

Checkpoint

If you completed all three exercises, you know how to:

Iterate over strings character by character
Pattern match with switch
Write functions with typed parameters and return values
Define enums and structs
Write and run tests with zig build test
Compare strings with std.mem.eql

You're ready for Phase 1. Delete the scratch project — we'll set up the real Monk compiler structure next.
